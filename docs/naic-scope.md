# NAIC scope decision

## Primary submission: Problem Statement 1 — Developer Infrastructure

Tcharize is in scope. Its core deliverable is a working localization platform built directly on N-ATLaS:

- browser-based N-ATLaS playground;
- typed REST API and Python SDK, with JavaScript SDK and CLI next;
- browser extension for whole-page localization;
- glossary, translation memory, review, quality, and evaluation tools;
- plain-language developer documentation and integration evidence.

This is a closer match than submitting under Voice-First Access because the platform's main reusable value is infrastructure that makes N-ATLaS easier to integrate, test, and deploy. Speech remains an important product capability.

## Secondary alignment: Problem Statement 2 — Voice-First Access

The extension and accessible read-aloud experience support the goal, but a PS2 submission would additionally require voice input through an official N-ATLaS ASR model and at least 50 documented real-user interactions. The product must not describe text-to-speech as N-ATLaS ASR; ASR listens, while TTS speaks.

## Not the current submission: Problem Statement 3 — Sectoral Fine-Tuning

Tcharize is currently horizontal infrastructure, not a single-sector fine-tune. PS3 would require a model derived from N-ATLaS, a clearly defined sector, a documented API, and a benchmark of at least 500 examples against the base model.

## Evidence still required before submission

1. Preserve redacted evidence from the live N-ATLaS endpoint in the technical report.
2. Complete at least two external beta tests for PS1.
3. Record real translation quality results by language and dialect.
4. Publish the repository and deployed build, then record a 3–5 minute demo.
5. Prepare the team profile and eligibility evidence.
6. Confirm every model and speech license before commercial scale.
